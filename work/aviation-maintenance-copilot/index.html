Copilot MRO is Flynapse.ai’s copilot for aircraft maintenance. I joined as founding engineer in May 2026 and, working as the primary engineer alongside the CTO with a few interns, built most of its core: the agent layer, Schema Auto Discovery, the RAG workflows, multi-tenant access and tracing.

What I built

Claude and LangGraph

I shaped the agent layer so the copilot supports both Claude and LangGraph without duplicating product logic, so choosing or comparing the two is an engineering decision, not a rewrite.

Fewer LLM calls

One agent workflow made 11 LLM calls. Each call adds latency and tokens, and with more steps there are more places for an answer to go wrong. I redesigned it into a path of 4–5 calls, which cut latency by 25% and cost by 40%.

Schema Auto Discovery

Each airline’s maintenance data is its own. Schema Auto Discovery lets the copilot use tenant-specific data safely, with controlled database access and a clear separation between discovering the data and executing SQL.

Checking answers

Answer quality is checked with guardrails and LLM-as-judge evaluation, and human review is the final step. I don’t treat an LLM judge as ground truth on its own: in my own study, four LLM judges each named a winner people didn’t back on 5 to 7 of 15 close comparisons.

Tracing

Arize Phoenix traces the copilot’s workflow, which is how a slow, expensive or wrong step gets found.

How it’s going

  • Live with a commercial airline, used by about 50 people.
  • The redesigned workflow is 25% faster and 40% cheaper, at 4–5 LLM calls instead of 11.
  • The same product logic runs on Claude or LangGraph.
  • Each airline’s own maintenance data is reached through Schema Auto Discovery and controlled database access.
